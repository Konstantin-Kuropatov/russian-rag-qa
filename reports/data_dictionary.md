# Словарь данных и правила подготовки

## Исходные сущности

| Сущность | Поля | Значение |
| --- | --- | --- |
| QA | `id`, `title`, `context`, `question`, `answers` | `answers` содержит массивы `text` и `answer_start`; их вложенная структура проверяется до извлечения единственного эталона. |
| Корпус | `corpus_id`, `context`, `title`, `processed_text`, `processed_title` | Единица retrieval. `processed_text` — предобработанная версия поставщика; для воспроизводимого первичного анализа используется исходный `context`. |
| Вопросы retrieval | `query_id`, `question`, `processed_text`, `title`, `processed_title` | ID этой версии не совпадают с QA ID. |
| Qrels | `query_id`, `corpus_id`, `score`, `split` | Положительные связи вопрос → фрагмент; отсутствие связи не гарантирует нерелевантность. |

## Подготовленные поля

| Поле | Определение и использование |
| --- | --- |
| `row_key` | `source_split:source_row`; уникальный внутренний ключ, поскольку исходные `id` имеют межсплитовые коллизии. |
| `split` | Исходный train / validation / test; никогда не перезаписывается. |
| `project_split`, `split_group` | Собственное групповое разбиение размеченного пула; seed=42. Для исходного неразмеченного test — `unlabeled_source_test`. |
| `context_hash`, `context_normalized_hash` | SHA256 точного текста и ключа после NFC, casefold и сжатия пробелов. Нормализация не является исправлением семантики. |
| `canonical_id` | Минимальный исходный `corpus_id` в группе одинаковых нормализованных текстов. Полная таблица соответствия остаётся в corpus_features. |
| `pair_hash`, `pair_occurrence`, `mapping_unique` | Сопоставление QA и retrieval по точному вопросу и контексту внутри split. Повторные пары явно помечены как неоднозначные по идентичности. |
| `answer_text`, `answer_start_raw` | Неизменённые опубликованные эталон и позиция. Пустая строка не означает доказанную неответимость. |
| `label_available` | Есть непустой опубликованный текст эталона. |
| `span_status` | Результат символьной проверки, не оценка смысловой корректности ответа. |
| `answer_start_fixed` | Исходная валидная позиция или единственное точное найденное вхождение. Для неоднозначных/нормализованных совпадений — NA. |
| `word_boundary_ok` | Найденный span не начинается и не заканчивается внутри последовательности букв/цифр. Эвристика не доказывает смысловую корректность. |
| `reader_eligible` | Точный span с допустимыми границами; консервативная техническая пригодность для extractive reader. |
| `retrieval_train_eligible` | Размеченный вопрос и непустой исходный контекст; символьный span не нужен для обучения поиска. Семантическая проверка пока не заменена автоматическим фильтром. |
| `q_*`, `c_*`, `a_*` | Характеристики вопроса, контекста, ответа соответственно. `chars` — Unicode code points; `words` — токены регулярного выражения, `unique_word_ratio` — доля уникальных слов. |
| `a_chars`, `a_words` и другие признаки эталона | Для неопубликованных labels — NA, а не фиктивный ответ длиной ноль. Сама исходная строка ответа остаётся неизменной. |
| `iqr_flag_*` | Индивидуальные флаги выбросов по IQR исходного train. Не используются как критерий удаления. Для неизвестных ответных признаков флаг также NA. |
| `c_e5_tokens`, `q_e5_tokens` | Длина по токенизатору multilingual-e5-small с префиксом и спецтокенами, без обрезки. Используется только для проверки длин перед будущим нейросетевым этапом. Первый бейзлайн TF-IDF работает со словами и от этого токенизатора не зависит. |
| `question_type` | Первое вопросительное слово среди первых трёх токенов; наличие частицы `ли` выделяется приоритетно. Это неполная лингвистическая классификация. |
| `context_reference_flag` | Поиск местоимений и указательных слов. Только повод для просмотра, не истинная метка неоднозначности. |
| `q_context_coverage` | Доля уникальных содержательных слов вопроса в контексте; фиксированный небольшой стоп-лист, без лемматизации. |
| `q_context_jaccard` | Jaccard множеств содержательных слов вопроса и контекста. |
| `q_answer_sentence_jaccard` | Jaccard с предложениями, пересекающими gold span. Недоступен без эталона; только EDA, не признак для инференса. |
| `a_context_char_ratio`, `a_position_relative` | Отношение длины эталона к длине контекста и положение начала span / длина контекста. Не вычисляются как фиктивный ноль при отсутствии аннотации. |
| `answer_retained_at_*` | Сохранится ли целый валидный span при обрезке полного encoder-входа до заданного бюджета. |
| `answer_window_*` | Есть ли среди всех окон заданного размера и overlap хотя бы одно, целиком покрывающее gold span. Размер окна относится к содержимому без специальных токенов. |

## Правила обработки

- Сырые файлы не изменяются; их версии и SHA256 фиксируются.
- Пустые labels исходного test остаются неизвестными. Пропуски не превращаются в negative / no-answer.
- Исправляется только единственная точная позиция текста; неоднозначная разметка сохраняется с флагами.
- Исходный текст не лемматизируется и не очищается перед поиском позиции: иначе offsets перестают соответствовать строке.
- Константные заголовки, ID и qrels `score=1` не используются как содержательные корреляционные признаки.
- Выбросы длин помечаются по IQR исходного train, но не удаляются без разбора содержания.
- Пересечения оцениваются и по исходным, и по нормализованным ключам; гарантии тематической или постатейной независимости не заявляются.
