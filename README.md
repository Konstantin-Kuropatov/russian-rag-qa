# Построение вопросно-ответной системы с использованием RAG

Годовой проект по направлению «Искусственный интеллект». Система будет находить подходящий фрагмент русскоязычного текста и с помощью языковой модели формировать краткий ответ с указанием источника. Основной акцент — на сравнении способов поиска и проверке качества ответов.

**Команда №14:** Куропатов Константин (индивидуальный проект)

**Куратор:** Ляпин Данила

## Данные

Основной датасет — [SberQuAD](https://huggingface.co/datasets/kuznetsoffandrey/sberquad): русскоязычные фрагменты статей, вопросы к ним и эталонные ответы. Для оценки поиска используется [версия SberQuAD для retrieval](https://huggingface.co/datasets/kaengreg/sberquad-retrieval) с [разметкой релевантных фрагментов](https://huggingface.co/datasets/kaengreg/sberquad-retrieval-qrels).

По результатам EDA: **74 300 вопросов, 50 364 опубликованных эталона ответа, 17 474 строки корпуса и 13 487 уникальных фрагментов после нормализации**. В исходном `test` ответы не опубликованы; это не набор размеченных вопросов без ответа. Контексты исходной `validation` встречаются в `train`, поэтому дополнительно подготовлено групповое разбиение размеченного пула.

## Чекпойнт 2 — разведочный анализ

[Выполненный ноутбук](notebooks/eda.ipynb) · [Выводы](reports/eda_findings.md) · [Словарь данных](reports/data_dictionary.md)

В EDA проверены пропуски, позиции ответов, выбросы длин, типы вопросов, корреляции, дубли и пересечения выборок. Подготовлено разбиение для будущего сравнения моделей. Отдельно проверено, как обрезка и нарезка текста могут потерять ответ.

**Первый бейзлайн — TF-IDF по словам и косинусная близость.** Его реализация и метрики относятся к чекпойнту 3. Далее планируется сравнение с BM25 и нейросетевым поиском на тех же данных.

Токенизатор `multilingual-e5-small` используется в EDA только для проверки длин. E5 выбран как компактный мультиязычный кандидат для будущего сравнения нейросетевого поиска: на его примере проверяем, что произойдёт при ограничении входа в 512 токенов. Его веса не загружаются. Первый бейзлайн TF-IDF использует разбиение на слова, а ограничение E5 к нему не относится. Подробнее — в [карточке модели](https://huggingface.co/intfloat/multilingual-e5-small).

## Воспроизводимый запуск

Используются **Python 3.12.12 и uv**. Из корня этого репозитория:

```bash
uv sync --locked
uv run rag-eda all
```

Первый запуск скачает закреплённые публичные версии данных и tokenizer, проверит SHA256, построит таблицы и выполнит ноутбук. Веса языковой модели не требуются. Версии пакетов зафиксированы в `uv.lock`, версии источников — в `config/data_sources.json`, контрольные суммы — в `reports/data_manifest.json`.

После скачивания анализ можно повторить без обращения к источникам:

```bash
uv run rag-eda analyze
uv run rag-eda notebook
```

Для интерактивной работы:

```bash
uv sync --locked --extra lab
uv run --extra lab jupyter lab
```

Результаты сохраняются в `reports/tables/` и `reports/figures/`, а версия ноутбука для чтения в браузере — в `reports/eda.html`. В `notebooks/` лежит только выполненный `eda.ipynb`. Его исходник в формате Jupytext — `src/rag_qa_eda/eda_notebook.py`; команда `rag-eda notebook` заново создаёт `.ipynb` из него. Сырые данные, подготовленные Parquet-файлы и кеш исключены из Git; их можно восстановить командами выше.

Проверки кода и правил подготовки:

```bash
uv run pytest -q
uv run ruff check src tests notebooks
uv run ruff format --check src tests notebooks
```
